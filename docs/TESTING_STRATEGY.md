# Testing strategy

## P5b requirements

Test original full manifest and selected immutable revision admission, malformed
disabled evidence, exact independent golden identity bytes, per-rule two episodes
and simultaneous transitions, inclusive freshness, unknown/SKIPPED continuity,
explicit previous/time/as_of/sample uniqueness, cross-series revision identity,
old replay without head/clock changes and conflicts without partial writes.
Use separate writer processes, injected failures between evaluation/signals/head,
rehashed result/signal/head tampering, exact SQL/FK inventory, local verification
versus missing/mutated origin, bounded pages/cursors/deadlines and hostile inputs.
Recovery probes cover exclusive destinations, sidecar/inode/link protection,
copy failure and restart. Deny sockets and check original stores are unchanged.

The eleventh `scripts/watchlist_journal_smoke.py` joins the ten existing installed
wheel/process harnesses in Quality, Compose, AMD64 and ARM64/QEMU. Each smoke
uses separate offline invocations and durable data across restart. Non-author QA
and a distinct REVIEWER produce own reproducible probes on the frozen candidate
commit/tree; author tests and the supplied eight design tests remain separate.
Unexecuted gates are not PASS. QEMU and process tests do not qualify native Pi
hardware or electrical power-loss durability.

## P5a requirements

Test full manifest parsing and public Python revalidation: fabricated DTOs,
missing UUIDs, non-sellable targets/candidates, languages/finishes/homonyms,
null/unknown, sealed optional set and incompatible parent changes. Independently
derive wlt1_ and canonical identity digests. Names/dates/aliases/unrelated valid
changes must preserve identity while unrelated invalid manifest content fails.

Exercise complete config/type/money bounds, threshold and +/-1 cent, free/null
shipping, exact sum arithmetic, all stock pairs, missing/stale prior, inclusive
freshness at0/max-age, future/unordered samples, explicit UTC/offset equivalence,
disabled invalid input, per-rule reasons and OR. Repeat canonical outputs and
deny sockets on imports, pure evaluation, CLI and smokes. Reject real provenance,
URL-like tokens, unknown fields, duplicate/nonfinite/large/deep JSON and bool-as-int.
Check evaluation leaves watchlist and all prior database bytes/logical content
unchanged and stores neither samples nor derived observed prices/results.

Use actual independent writer processes for CAS races, replay/token conflicts,
old replay after newer revisions, rollback/process interruption/reopen. Corrupt
schema inventory, owner/version, identity, full history, request command/digest,
ordinal/current pointer and foreign keys; coherently hashed invalid data must
still fail. Test hostile stored sizes/types before materialization, bound/filter
keyset cursors, locks and one total budget. Inject copy/IO failure, existing
destination/sidecar collisions, links and exclusive validated restore; preserve
unrelated files. Recovery tests establish local process behavior, not electrical
power-loss durability or authentication of coherent privileged tampering.

The tenth watchlist harness runs with every prior harness through an installed
wheel outside the checkout, Compose and both architecture jobs. Runtime remains
offline. QA and a separate REVIEWER derive additional probes on the exact final
SHA/tree and inspect all four full CI logs. Author tests/docs are distinct evidence;
substantive fixes require renewed final-candidate checks and attestations.

## P8b requirements

Fake transport tests cover frozen text, private binding/original recompute,
strict receipts, TLS/no proxy/redirect/retry, reflected secrets, malformed JSON,
oversize/truncation and supervised DNS/read/drip deadlines. Independent processes
exercise claim concurrency, interruption, rollback/restart, old-owner fencing,
stale backups and whole-ledger quarantine including absent deliveries. Distinguish
local history checks from opaque source commitment recomputation. Simulated IO
and QEMU do not prove native Pi electrical durability.

The ninth installed-process harness joins every existing wheel/Compose/AMD64/
ARM64 smoke offline with fake transport only. QA derives its own oracles/probes;
a distinct REVIEWER audits final SHA/tree and all four complete CI logs. Author
tests remain separate evidence. Manual T17 is outside CI and requires specific
operator authorization; green CI never substitutes for real receipt evidence.

## P8a requirements

Test public explicit comparison admission against original captures, including
coherently modified journal evidence and forged or mutated receipts/JSON/DTOs.
Derive alt1 independently. Check one evt3 in two cmp3 windows retains one alert
and two complete associations, two destinations remain distinct, replay preserves
messages/evidence/first clocks and intrinsic conflicts roll back all rows.
Four reviewed real R0-to-R1 units produce zero alerts; positive events use only
the authorized synthetic profile. No new source acquisition is permitted.

Exercise strict intent/event validation, duplicate/nonfinite/oversized JSON,
hostile SQLite cells guarded before loading, inventory/FK/digest/version
corruption, Unicode/control/bidi rendering, aliases/links/sidecars, bounded keyset
pages during insertion, shared deadlines and locks. Preview and recompute must
be read-only; distinguish local consistency from origin-backed equality.
Temporary SQLite tests use real writer processes, termination inside a write
transaction, rollback, reopen and consistent SQLite backup/restore. These prove
neither physical power-loss durability nor native Raspberry Pi behavior.

The eighth installed-process harness joins all seven previous harnesses in wheel,
Compose and both architecture jobs, preserving runtime network/UID/fixture/data
restrictions. Independent QA derives additional probes and its own hash oracle;
a different REVIEWER audits final source/contracts/security and all four CI logs.
Both attest the exact frozen candidate SHA/tree. Author tests are separate evidence.

## P4c journal requirements

Test the public request+verified-captures admission, not manufactured result JSON.
Cover real four-unit R0/R1 zero-event comparisons, baseline/no_discoveries and
explicit synthetic positives. Preserve source bytes/schema and v1/v2/v3 goldens.
Two different windows sharing evt3 must retain distinct parent evidence. Check
independent canonical SHA recipe, first-insertion clock, replay and conflict,
full nested grammar including bool/int, duplicate/nonfinite/deep JSON, hostile
SQLite scalar/payload sizes, owner/schema/foreign keys/counts/ordinals, safe paths,
finite locks/deadlines, paging and local versus origin-backed verification.

Storage integration exercises fault-injected rollback, simultaneous real processes,
process kill before commit/reopen, recovery and validated backup/restore. External
wheel/container seventh harness joins the previous six and runs all operations
between independent offline processes. Author tests are not independent QA.
Nonauthor QA derives additional probes and independent identity/digest expectations;
REVIEWER independently audits the exact frozen SHA/tree and four complete CI logs.
Changed candidates require renewed attestations. QEMU/process failure is not
native Pi/electrical power-loss certification.

## P1c requirements

Test exact two-package registry membership, tampered revision/times/policy/license/
projection/hashes, caller registries and forged Python values before retention.
Keep R0 bytes/fingerprints and v1/v2 goldens; verify R1 rejection by old routes.
Exercise schema2 new/migrated DBs, replay versus cross-revision conflict, rollback,
all envelope/row/parent validation including unselected units, one ro snapshot
with an interleaved writer, deadlines/locks, copy/reopen and recovery identity.

Eight real scenarios (four units, empty/coherent-set manifest) must return
no_discoveries with zero events and both packages' acquisition evidence. Reverse
and equal capture times fail. Explicit synthetic profile tests novelty/aliases,
metadata-only and candidate-to-accepted suppression, historical union/reappearance,
duplicates/contradictions, incomplete evidence, mixed scopes and receipt forgeries.
The sixth process harness joins every previous one; CI runtime is offline.
Independent reviews bind final SHA/tree and all four complete job logs.

## P4b requirements

Strict v2 requests and Python constructors, exact unit/paths/context/null,
full envelope/partition/count validation, unsupported/forged/mixed provenance,
partial/failed/rejected/missing evidence and chronology require negative tests.
Persist synthetic scopes through persist_capture; test accepted/candidate union,
aliases, metadata/binding evolution, duplicates/contradictions, empty/reappearance,
stable cmp2/evt2/order/replay/backup restore and global versus selected counts.
The unchanged real package supplies all four baselines with empty and curated
set bindings, original indexes and equal-time reimport rejection. No synthetic
positive is represented as a real provider change. V1 guards/hashes regressions
stay intact. Real temporary SQLite tests include corruption in unselected units,
byte/lexical guards, parent closure, locks/deadline and interleaved writer snapshots.

The new scoped_capture_discovery_smoke joins every prior harness in outside-tree
wheel, Compose and both architecture jobs. It seeds/closes/reopens in separate
offline processes, verifies installed import, UID10001/fixtures ro and complete
logical/schema/content nonmutation plus restore equality. Separate QA and final
REVIEWER inspect exact frozen SHA/tree and all four CI job bodies. Unexecuted
mandatory gates are FAIL; QEMU never qualifies physical Pi power loss.

## P1b requirements

Test exact minimum field/path/commit/blob/projection lock, non-executable grammar,
duplicate/decoy fields, required ES/EN/import relationships, bounds, Unicode,
forged objects and self-attested policies. Real fixtures contain only the approved
licensed minimum; adversarial mutated inputs are temporary synthetic scenarios.
Independently contrast original fixed bytes and full MIT notice, not just author output.
Test conservative curated identity, unknown finish and no automatic promotion.

Real SQLite tests cover explicit v1 backup/migration, populated/empty history,
exact original fingerprints/rows, no auto-upgrade, fault/interrupt rollback,
legacy scope, capture immutability, empty/partial/rejected distinctions,
replay/context conflict, bounded snapshots, schema/FK/count/policy tampering,
locks/IO and verified v1/v2 restore. Discovery observed/mixed selections must fail.
CLI/process harness checks offline import, reopen, query, replay and recovery
through installed wheel, Compose, AMD64 and ARM64 QEMU. Preserve every earlier
regression/harness; legitimate future-version test advances 2→3 with schema2.
QA/REVIEWER are distinct nonauthors and inspect detached final SHA/tree.

## P4a requirements

Unit/contracts test full reference keys, historical accepted/candidate union,
candidate->accepted, reappearance, existing UUID/new alias, accepted non-set kinds,
name/date changes, exact null/language/variant, duplicates/contradictions,
deterministic IDs/order/window changes, bootstrap and attested empty history.
Strict request/Python boundaries cover forgery, duplicate keys, version and
byte/depth/node/string/history budgets without silently truncated success.

Temporary SQLite tests distinguish empty/missing; metadata+rows share one
snapshot against a concurrent writer. Test ownership/schema/integrity/target
closure/counters/provenance/index tampering, lock/deadline/IO and noncreation/
nonmutation. Empty scope attestation is distinguished from stored existence.
No drill touches user databases. CLI tests check codes0/2/1, redaction and no
network. Installed/container harnesses seed through P3a in another process,
repeat and backup/restore while checking full logical content/schema/version.
Preserve every P0/P1a/P3a smoke and include all new runtime in coverage.
Independent QA/REVIEWER derive extra risks and inspect exact final SHA/four CI
bodies. Working-tree checks remain provisional until tied to Git objects.

## P3a requirements

Boundary tests cover explicit UTC capture/offset equivalence/conflicts, provenance,
full dataclass/manifest/resolution revalidation, safe indexed rejections, sealed
generic observations, version/null/order/duplicate/replay context and input bounds.
Real temporary SQLite integration covers reopen/history/identity closure,
foreign-key/check/uniqueness constraints, intermediate write failure rollback,
process exit before/after commit, atomic initial DDL rollback/current no-op,
foreign/future/altered schemas, finite contention, simulated IO/full failures,
corruption, permissions and consistent backup/restore including unsafe paths,
links, existing files and sidecar collisions. Drills touch only temporary DBs.

CLI/logging tests assert separate data/local exit codes, error null counters,
confirmed-versus-attempted rows, no-network processing, redaction and P0/P1a
compatibility. The [persistence smoke](../scripts/observation_persistence_smoke.py)
checks durable content, candidates, later capture, stable replay and recovery via
separate invocations of installed wheel, Compose and each architecture container.
Container cases assert UID10001 and mounted private data directory, use a unique
named volume and read-only fixtures with networking disabled, and remove only
their own test volume. Existing five P1a and Foundation smokes remain mandatory.

Independent QA and REVIEWER are different agents from authors and each other;
each checks an isolated checkout of the committed candidate. Working-tree tests
are provisional until tied to exact reviewed SHA/tree and published CI. QEMU and
process interruption do not establish physical Pi power-loss durability.

## P1a requirements

Core and adapter unit/contract tests cover UUID and relationship constraints,
explicit cross-provider and ES/EN aliases, homonyms, printing variants, unknowns,
sealed distinction, text card numbers, missing/null/wrong-type fields,
incompatible versions, duplicate keys/IDs, conflicting bindings, bounded work
and extra-field minimization. CLI integration tests verify deterministic results,
mixed/all-rejected/empty/global failure distinctions, no network, sanitized errors
and additive logging compatibility. P0 regression tests remain mandatory.
Fixtures are synthetic and provenance is recorded under `tests/fixtures`.

Installed wheel smoke runs outside the source tree. The same five catalog cases
run in Compose and both architecture images, alongside existing P0/non-root
checks. Docker catalog smoke disables networking and mounts fixtures read only;
Compose catalog has `network_mode: none`. QA and final REVIEWER are distinct
read-only agents, independent from authors and each other, and review exact
committed SHA/tree. Their test executions and findings belong in the PR ledger.

P0 tests prove observable behavior and failure paths without network access. Test configuration defaults, explicit env files, process-environment precedence, invalid settings, and secret-safe errors. Test CLI version and diagnose outputs, exit codes 0/1/2, writable and unwritable work directories, and absence of network calls. Test JSON shape, UTC timestamp, run_id propagation, allowlisting/redaction, and no duplicate logging handlers. QA should derive cases from risks and acceptance criteria rather than merely restating code paths.

Build and install the wheel outside the source tree to prove packaging; run version and diagnose from the installed wheel. Container smoke tests must run on `linux/amd64` and `linux/arm64`: build, version, valid diagnose, invalid configuration failure, and effective non-root UID. The CI ARM64 path uses QEMU emulation and does not prove operation on a physical Pi. Compose must run both one-shot services.

Fixtures belong under `tests/fixtures/`. Name synthetic inputs `synthetic_*` and describe what they model. Future real-source fixtures must be minimal, sanitized, legally permitted to retain, and accompanied by provenance and capture date. Never commit credentials, personal data, full payload dumps, or source data whose retention is unclear. Commercial provider contract tests and database recovery tests begin in their owning phases.

Use the [quality gate commands](QUALITY_GATES.md). Coverage applies to own runtime code with thresholds of at least 85% lines and 80% branches; critical modules must not be excluded to raise a percentage. Preserve failed-case output, tool versions, environment, and commit in the phase evidence report.
